# 载体实战手册（Domain Playbooks）

每节结构：先做什么 → 硬规则（数值）→ 禁止 → 验收。通用的字、色、网格、动效参数见 `typography_color_and_grid.md`，这里只写载体特有的规则。

## 0. 载体模式与三档刻度〔DT〕

| 模式 | 载体 | 变化度 / 动效 / 密度（1–10） | 首屏任务 | 允许 | 不适用 |
|---|---|---|---|---|---|
| Persuade | 落地页、官网、定价、活动、作品集 | 7–9 / 6–8 / 3–5 | 说清卖什么、给谁、一条硬事实 | 大字、真实大图、一个时刻 | 20 行数据表 |
| Operate | Dashboard、后台、设置、工具、表单 | 3–5 / 3–4 / 5–7 | 直接进入任务 | 系统字体、密集表格、同级指标并列（无渐变、无图标圆）| Hero 大图、编排式入场 |
| Read | 文档、指南、长文、更新日志 | 5–6 / 3–4 / 3–4 | 目录与第一段 | 稳定锚点、统一的代码块/表格/提示样式 | 抢读的装饰 |
| Experience | 海报、展示、单件作品、游戏化一次性页面 | 8–10 / 6–9 / 2–3 | 作品本身 | 一个视觉概念贯彻到底 | 营销脚手架（Hero+logo 墙+特性网格）|

刻度怎么落地：变化度 → 不对称程度与原型选择；动效 → 动画元素个数（≤3 时只留交互反馈）；密度 → 字阶比例（1.125–1.333）与三档间距的绝对值。模式按"被要求的载体"判，而不是按产品：工具的落地页是 Persuade，时装品牌的文档是 Read。

## 1. 落地页 / 官网（Persuade）

### 1.1 先做
1. 写下业务类型（软件/硬件/实体产品/服务/到店场所，见原型 D）、卖什么、谁买、**唯一主操作**（"预订房间"、"开始免费试用"；场所没有交易时为"导航到店"）和真实素材清单（logo、截图、照片、价格、地址、时间）。〔TS〕
2. **先写全部文案，再排版**：h1 说出品类与买家（或地点）；首屏一条硬事实；每个标题含名词；按钮 = 动词 + 宾语。〔TS〕〔AFD〕
3. 把页面写成"屏幕清单"：每行 = 区块 id、它的一个观点、它的画面、占 1 屏还是 2 屏、是否承载"时刻"。

### 1.2 首屏
- 首屏只有 Hero，下一区块的任何部分在 1440/1024/768/390 都不露出；Hero 内容在粘性导航下留出 `导航高 + 96px`（或固定的 `--padt` 120/96）。〔TS〕〔TU〕
- h1 ≤3 行（任意宽度），一个朴素的断言，不写口号；副标题 ≤20 个英文词 / ≤40 个汉字且 ≤4 行；按钮 ≤2 个且在所有宽度的首屏内；Hero 内文字元素 ≤4 个。〔TS〕〔DT〕
- Hero 画面 = 客户的真东西（产品、场所、作品、真实界面），不是色块或氛围。画面结束于 Hero 内，不被折线切成半张。〔TS〕
- Hero 构图按"手里有什么素材"选，不按喜好：有好照片 → 满版照片（文字放在照片安静的暗部，或照片下方的纯底上）；有真实界面 → 分栏或居中窗口（产品窗口被画框边缘裁切）；产品实物 → 产品整体占内容宽 ≥80%；什么都没有 → 一句超大陈述 + 后续真实作品。三页之内不重复同一种 Hero。〔TS layout-v4〕
- 不做：大数字指标 Hero、居中标题 + 双按钮 + 光斑、版本号胶囊、滚动提示、Hero 底部装饰字带（`BRAND. MOTION. SPATIAL.`）、浮动的第二张卡片。〔AFD〕〔DT〕

### 1.3 区块节奏
- 每个区块 1 或 2 屏高；内容填充率 ≥0.55；过短的引文、logo 行、数据行并入上一区块，不单独成"条"。区块之间只用整块底色切换或留白，不画线、不加阴影。〔TS layout-v4〕
- 默认内容形状：标题 ≤8 个英文词 / ≤16 个汉字 + 副段 ≤25 词 / ≤50 字 + 一个视觉或一个 CTA。更多内容必须由该区块的任务证明。〔DT〕【补强：中文换算】
- 8 个区块中至少 4 种不同的布局家族；不连续 3 个同构左右分栏；同一意图的 CTA 不出现两种说法（"联系我们"+"聊一聊" = 失败）。〔DT〕
- 区块头：标题在上、说明紧贴其下；要双栏就做干净的"左标题、右对齐正文"，不做右上角飘浮的小段文字。eyebrow 数量 ≤ ⌈区块数 / 3⌉，且写话题而非编号。〔DT〕

### 1.4 卡片与特性展示〔TS cards〕
- 卡片"几乎不存在"：比页面高一级的底色、墨色 8–14% 的 1px 线、内边距 32（≥1024）/ 28 / 24（手机）、静止无模糊阴影；圆角取所选族的 lg（soft 为 20）。
- 两层封顶：卡片 > 画板（一张"有光"的真实图片）> 片段（真实产品界面，按真实尺寸，被画板边缘裁切）。不做卡片 > 网格纹画板 > 白色 UI 卡；不做卡中卡。
- 片段展示产品处理的对象（代码评审工具 = 红绿 diff + Accept；开票工具 = 一张发票），不是通用 Dashboard、聊天框或指标卡。片段最小宽度：聊天 140、清单 160、终端 280、日历 280、代码 365、文档 400、窗口 456（px）；片段内字 13px、元信息 12px，不再更小（低于 12px 由 `render_audit` 判 FAIL）。
- 一个片段一个强调（正在处理的行、被标记的日期）；其余状态用墨色深浅。
- 卡片标题一行（20/18px、500），其下最多两行 16/24 的墨色正文（≤46ch），不用小号灰字写正文；同一行卡片标题与画板顶部对齐。
- 替代"三张等宽图标卡"：一个主导 + 两个辅助的不对称组合；或一列靠间距分组的清单；或一个真实界面片段 + 三条说明文字。

### 1.5 证据、导航与收尾
- Logo 墙：只放 logo（真实 SVG，深浅两版），不在下方印行业标签；位于 Hero 下方而非其中；只放真正的客户。〔DT〕
- 证言：真实引语 ≤3 行，署名干净；不编造"三个故事 + 数字 + 金句"的完美证言。〔DT〕〔TS copy-tells〕
- 导航：桌面一行、高 ≤80px（常用 72/56）、4–6 个单词名词、一个主按钮；不透明底 + 1px 底线；不缩放、不隐藏、不变色、不毛玻璃。手机：全屏菜单，行高 56px。〔TS system〕〔DT〕
- 收尾与页脚合并为一个区块：第一行是收尾（一句话 + 主按钮），第二行是链接与法务。页脚不放版本号、构建号、城市时间天气条。〔TS〕〔DT〕
- 照片：真实或注明的替身；同一张不出现两次；一行一个比例；照片下不写说明，授权署名统一放页脚一行。〔TS〕

### 1.6 验收
- 每个 `scrollY = k × 视口高` 截图恰好一个区块；首屏说清卖什么 + 给谁 + 一条硬事实；左右内容边线全页一致；`render_audit` 无横向溢出、无 <44px 的可点区域（手机）、无对比 FAIL。

## 2. Dashboard / 工具 / 表单 / AI 产品（Operate）

### 2.1 先做
- 从一个真实功能开始，不从外壳（导航、侧栏、页脚）开始；走通一条真实任务路径再扩展。〔TU〕
- 盘点现有设计系统与组件，沿用其语义与命名；新 token 映射到旧角色，不另起一套。〔UD〕〔TU〕

### 2.2 视觉规则
- 一个调好的家族撑全场；固定 rem 字阶，比例 1.125–1.2；页面标题 ≤28px，组件标题 ≤24px；正文/表格 14–16px。展示字体不进标签、按钮、数据。〔TU〕〔DT〕
- 色彩"克制"：带色调的中性两层（画布 + 侧栏/工具栏）+ 一个强调色 ≤10%，只给主操作、当前选中、焦点；状态词汇标准化（hover、focus、active、disabled、selected、loading、error、warning、success、info）。非活动态不用满饱和色。〔DT〕
- 指标卡：等宽数字；增减用符号 + 箭头图标 + 颜色三重编码；一个主指标可以更大，其余同级；禁止渐变卡、图标装彩色圆、营销式大字。指标数字不是标题标签。〔TU〕〔DT〕
- 卡片不是默认容器：同级数据用对齐与间距成组；只有当"浮起"传达真实层级时才用卡片；永不卡中卡。〔DT〕
- z-index 用语义刻度（dropdown → sticky → modal → toast → tooltip），写成 token，不写 999/9999。〔DT〕

### 2.3 表格
- 数字列右对齐 + tabular-nums；文字列左对齐；表头与列内容同对齐方向。〔UX〕
- 一种分隔方式：行底线 **或** 斑马纹 **或** 纯间距，三选一，不上下双描边。〔DT〕
- 表头吸顶；可排序列有 `aria-sort`；1000+ 行分页或虚拟滚动；长文本单行省略时提供完整查看路径（tooltip/展开），flex 子项加 `min-width: 0`。〔UX〕〔UD〕
- 空、加载、错误三态：加载用与最终布局一致的骨架屏，不在内容中间放转圈；空状态说明这里会出现什么并给出第一步操作。〔TU〕〔DT〕

### 2.4 表单〔TU〕〔DT〕〔AU〕
- 标签在输入框上方，标签→字段 4–8px，字段→下一标签 16–24px；占位符不当标签。
- 输入框在相近底色上要有可见的填充与边框（静止、hover、focus、error 四态都可见），焦点环不能替代静止边界。
- 输入框与并排按钮等高（以按钮高度 token 为准）；相邻按钮同高同内边距，层级靠变体（主/次/幽灵）不靠尺寸；按钮文字不换行（`white-space: nowrap`）、按钮不被挤压（`flex-shrink: 0`）。
- 输入框内图标：图标到边缘距离 = 图标到文字距离；`padding-inline-start = inset + iconWidth + inset`。原生 `<select>`：`appearance: none` + 同 inset 的自绘箭头 + `color-scheme` 适配深色。
- 失焦校验；错误文字在字段下方，带图标，`aria-describedby` 关联；错误说清发生了什么、怎么修，不道歉、不含糊。异步按钮有 loading 态且处理中禁用。可撤销的操作用"撤销"代替确认弹窗。〔AFD〕〔AU〕〔DT〕
- 手机端输入框字号 ≥16px，避免 iOS 聚焦自动放大。【补强：具体阈值】

### 2.5 浮层与键盘
- 原生 `<dialog>` + `inert`、Popover API、锚点定位优先；浮层逃出容器（portal / fixed），不被 overflow 裁切。〔DT〕
- 弹窗：可见的关闭按钮 + Esc 关闭；焦点进入时困在弹窗内，关闭后回到触发器。〔AU〕〔TU〕
- 焦点环：`:focus-visible`，≥2px、偏移 ≥2px、对组件与页面底色均 ≥3:1、出现无动画、全站统一。〔TU〕

### 2.6 AI 产品界面〔UD interaction〕
- 按真实协议映射状态：`idle / clarifying / ready / awaiting_confirmation / running / partial / completed / error / cancelled`；"请求取消中""仍在运行""已取消"分别呈现。
- 进度可核算时显示确定进度；不可估时显示有意义的现状（"正在读取第 3/12 个文件"），不是无限转圈。
- 展示依据（来源、引用）、可编辑草稿与差异；对外动作由真实权限控制；失败时保留输入与已完成部分。

### 2.7 验收
- 关闭颜色（灰度截图）后状态仍可区分；同一动作在所有屏幕同名同样式（按钮"发布"→ 提示"已发布"）；用 `visual_critique_and_polish.md` §5 的极端内容压测后不破版。〔AFD〕

## 3. 数据图表与示意图

### 3.1 图表：先问题，后图型〔LF〕〔UD〕
1. 写下读者要回答的问题；先判数据形状（类目比较 / 时间序列 / 占比 / 正负 / 分布 / 关系 / 层级 / 流量），形状是选图主键。
2. 至少比较 3 个候选，记录淘汰理由；选择 = 语义合适（每个点线面背后有真实单位）∩ 视觉合适（标签放得下、读者能按预期时间读完）∩ 叙事合适。
3. "一张表或一段话能不能做同样的事？"能 → 不画图。〔DD〕

| 数据形状 | 首选 | 注意 |
|---|---|---|
| ≤8 类比较 | 横条（类目名长时）/ 竖条 / 点图 | 条形起点为 0，**不断轴** |
| 时间序列 | 折线；≤30 天逐日可用细线或棒棒糖 | ≤5 条线；直接在线尾标注 |
| 占比 / 100% 构成 | 百格点阵（waffle）或横向堆叠条 | 饼/环 ≤5 类 |
| 带正负 | 发散条形 | 中点 = 真实基准 |
| 前后两时点 | 哑铃图 | 交叉过多的斜率图不画 |
| 分布 | 抖动点带、箱线（五数+异常值） | 箱线须说明须的定义 |
| 增减分解 | 瀑布 ≤6 级 | |
| 层级 + 份额 | 两层矩形树图 | 面积已编码数值，颜色不重复编码 |
| 极端值 | 让它冲天 / 主图 + 放大小图 / 撕柱不撕轴 | 绝不断轴 |

- 面积编码用 `Math.sqrt(v)` 换半径；数值与视觉严格成比例。演示数据用确定性伪随机（seeded），刷新两次一样。〔LF〕
- 地图只在用户明确要求地理分布时使用；面积是地理面积不是数值，副标题写明 `shade = value`。中国地图需合规数据源与审图信息。〔LF〕

### 3.2 图表的视觉语法
- 卡片四件套：**结论式标题**（写判断不写图型："华东在 Q3 反超华南"，不写"月度销售额柱状图"）+ 副标题（单位、图例、时间范围）+ 图 + 来源行（句首大写的小字，不用全大写加字距）。〔LF〕【补强：来源行去全大写】
- 实心、不透明、不发光、无渐变滤镜、无阴影、无 3D；质感来自明度对比与形状。唯一例外：叠加型图里透明度本身编码密度。〔LF〕
- 网格线低对比（墨色 10–16%），3–7 条或不画；单系列不放图例；小数据集直接标注而非图例；图例靠近图。〔VD〕〔UX〕
- 两种家族按场合选：**速读**（粗形状、2px+ 线、预聚合、<10 秒读完：周报、Dashboard）与**细读**（一点 = 一条记录、0.5–0.7px 发丝线、不聚合、30 秒+：年报、海报、长文）。数据少时"细读化"的方法是单位分解（1 点 = 1 人 / 1 个百分点），只拆诚实单位，并配环境结构层（账本横线、刻度、引线），而不是只画数据加一根底线。〔LF〕
- 交互三问：①这根线/点背后有真实记录吗？没有 → 禁止加交互；②不点能读懂吗？<50 个元素且两端有标注 → 静态即可；③>50 个元素或多段路径 → 必须 hover/固定（热区可用 9px 透明孪生线）。tooltip 显示精确值，键盘可达。〔LF〕〔UX〕
- 字：图内数值可加粗一档，轴标签用中等字重；图内文字渲染尺寸 ≥11px（屏幕），装不下改 hover，不缩字硬塞。〔LF〕【补强：以渲染像素计】
- 无障碍：给出文字摘要或 `aria-label` 写关键结论；颜色从不单独承担含义。
- 一页图表 ≤6 张，每张承担一个独立结论；一组图共享一种色彩系统、模板不重复。〔LF〕

### 3.3 架构图 / 流程图〔DD〕
- 复杂度预算：节点 ≤9、连线 ≤12、强调元素 ≤2、注释 ≤2；超出则拆成"总览 + 细节"两张。
- 连线：直角折线 + 半径 8 的圆角弯（紧凑时 ≥6），共线才用直线；不重叠走线（必要的交叉用"跨桥"，平行路线错开 ≥12px）；标签距连线 6–10px 并有不透明底。
- 所有坐标、尺寸、间距为 4 的倍数；节点内边距 8/12/16，节点间距 20–48，圆角 4/6/8；线宽 0.8 / 1 / 1.2。
- 语义角色而非随意上色：`paper / ink / muted / soft / rule / accent / link`；一个强调色只给 1–2 个焦点节点；图例在图外、作为图下的横条。
- 默认无容器背景、无边框，直接坐在页面纸上；Mono 字体只给技术内容（端口、命令、URL、字段类型），名称用无衬线。
- SVG 有 `role="img"`，第一个子元素是 `<title>`，并有 `<desc>`；ID 加前缀避免冲突。
- 动效默认静态；需要时只用流动虚线（周期规则见 `typography_color_and_grid.md` §5.4）或分步揭示，且不改变静态含义。〔DD〕〔DM〕

## 4. 海报 / 平面 / 信息图 / SVG 构图（Experience）

### 4.1 先做
- **需求高于惯例**：不存在通用的海报尺寸、网格、正文字号、边距、DPI、字数或栏数。先确认主办方/印厂/平台的规格并记录来源；所有通用数值标为"经验值"。〔PP〕
- 写下：主体（必须一眼认出的一个人/物/场景/想法）、意图（公告、宣言、观察、标本页）、精确文字（用户给的原样保留，不翻译）、画面角色。复杂题材选**一个**具体视觉隐喻，不图解每个要点。〔MC〕
- 画 3 张灰阶矩形级构图候选（同一份真实内容），比较主轴、主图比例、阅读顺序、对齐关系，再选一张深化。〔UD composition〕

### 4.2 构图硬规则
- **一个焦点事件 + 一个释放区**：超大字、极端裁切、一个巨物、一次套印碰撞或一处反常的尺度关系，选一个；其余元素要么支持它，要么让出空间。缩略图下焦点一眼可辨、释放区明显更安静。〔MC〕
- 主体占画面 45–80%，至少一边被果断裁切；空白 25–55%；外边距为页宽 5–9%；对齐一条隐形左线或 2–3 栏网格；一个刻意的破格（偏心裁图、漂浮的词、旋转标签，只一个）。永不全部居中，永不平均分布。〔MC〕
- 字与物碰撞：标题穿过、覆盖、绕开或紧贴主体，同时保持可读对比；不把所有字放进主体上方的"安全区"。〔MC〕
- 字阶跃迁：最大字 / 最小字 = 5–12×（字即主体时 12–20×）；展示文案 2–8 个英文词（中文 ≤16 字）；一个主展示声部 + 一个功能声部。〔MC〕
- 文字是视觉的一部分，但永远可读：任何文字、图形不掉出画布、不意外重叠，每个元素有呼吸。〔ACD〕
- 精修不加东西：想再画一个形状时停下，问"怎样让已有的东西更像作品"。〔ACD〕

### 4.3 印刷与输出数学〔PP〕
- 成品字号：`最终字号 = 设计字号 × 物理画幅宽 / 画布宽`（高度同比，不允许宽高比例不同）。18pt 是 PowerPoint 屏幕演示的经验值，不是海报下限。
- 有效 DPI：`有效 DPI = 源像素 / 成品放置英寸`，宽高分别算，取较低值；文件元数据里的 DPI 不代表质量。
- 对比：所有前景/背景配对都声明并实算（正文 4.5:1、大字 3:1）；先打缩小样，再看全尺寸样。
- 颜色之外再加形状/标记/线型/位置/文字的冗余编码；灰度下仍可区分。
- 阅读顺序：可见标题在前，然后连续的阅读顺序；关键词保持为原生文字而非位图；二维码旁必须有可见的网址文字。替代文字描述目的与结论，不写"一张……的图片"。
- 人工门：自动化只能发现技术缺陷，不能证明无障碍或科学准确性。

### 4.4 SVG 与矢量
- SVG 用于标识、图标、连接关系、可编辑几何；照片、光影、材质用合适分辨率的位图。〔UD vector〕
- `viewBox` 与成品比例一致；坐标落在 4 的倍数；描边宽度与圆角来自 token；文字保持 `<text>`（交付印刷时另出转曲副本）。〔DD〕〔UD〕
- 图标：一个轮廓表达一个对象或动作；统一网格、线帽、描边（1.5–2px）、安全区；按 16/24/32px 实际尺寸检查，小尺寸丢细节时重画简版。〔UX〕〔UD〕
- 禁用手绘感路径、`feTurbulence` / `feDisplacementMap` 假纸纹；做不到真实素材，就不放插画。〔DT〕
- 不重画真实品牌 logo；虚构品牌才设计自己的标志（单色剪影起步，缩小后仍可辨）。〔TS〕〔UD brand〕

### 4.5 信息图
- 先写一句主结论；用"一个大问题 → 3–5 个证据块 → 一个结论"的阅读路径；每个证据块的数字配单位与来源。【补强】
- 图表部分遵守 §3；图标从一个图标族取；颜色系统全图唯一。

## 5. 幻灯片 / 演示

- 每页一个主要结论，写成完整断言作为标题（"新流程把交付周期缩短了一半"而不是"交付周期"）；正文只放支撑这条结论的证据。〔LF〕【补强：断言式标题】
- 字号一次定好、全稿 ≤5 档；最小字号 ≥ 画面短边的 2.6%（1920×1080 → 28px，1280×720 → 19px）；标题 ≤2 行，手动断行，不留孤字。〔VD〕
- 所有标题共用一条左边线；数一数整套幻灯片的不同左边线数量，越少越好。〔VD〕
- 每页一个主导元素；不做一排等大的方块（"四个黑框写四个步骤"）。〔VD〕
- 底色变化跟着叙事的"幕"走（新的一幕才换色），相邻底色以明度区分（亮/中/暗），不只换色相。〔VD〕
- 图表遵守 §3；一个数据强调色只落在被讲到的那根柱/那条线上。〔VD〕
- 用户给的 PPT、截图、HTML 只作版式参考，不是数据来源；数据、单位、口径、来源必须来自用户材料或标明的计算。HTML/PDF 不得冒称可编辑 `.pptx`。〔LF〕
- 验收：把全部页做成缩略图联系表，3 秒扫视能说出每页结论；用 1/3 尺寸检查最小字是否可读。

## 6. 视频 / 品牌片 / 动态设计〔VD〕〔PLM〕〔GM〕

- **色随故事**：全片 2–3 个色场，只在叙事转折处切换；相邻色场明度分离；色场之间硬切，内容可淡入淡出，底色永不交叉溶解。
- **一个数据强调色**：品牌色只落在旁白正在讲的那根柱/那条线/那个数字上。
- **字**：1080p 下五档：展示 200–260、数字 112–132、标题 64–72、标签 32–36、注释 28（手机下限 28px ≈ 短边 2.6%）；一个家族、≤2 字重；展示字距 −0.03 至 −0.05em、行高 0.9–1.0（中文展示字距 0、行高 1.15–1.3）。
- **布局**：所有标题一条左边线；每个镜头一个主导物；不出现一排相同方块；无渐变、发光、静止投影、玻璃面板、装饰形状。平涂场显得单调时，画出题材自身的结构（日历周网格、节拍网格、代码行号槽、地图等高线），线为场内墨色的 10–16%，全片一个母题。
- **图表**：面积填充 ≤15%，柱为方角，单系列无图例，网格线 3–7 条或不画，强调在旁白说到的那个词上落下。
- **转场**：换幕 = 硬切或划像，色场间永不交叉溶解；"同一事物换一种说法" = 在说到那个词时原位翻页。大幅镜头运动只用于揭示问题或结果；讲解期间保持焦点与阅读时间。〔GM〕
- **产品发布片**：一个形状贯穿不剪（每个状态都是同一元素的尺寸/圆角/颜色形变）；内容切换用短暂模糊；只用闭式弹簧、至多一点点过冲；由光标的真实点击和拖拽驱动变化；空镜头是 bug，镜头推拉让每个状态占满画面；音乐先行，节拍网格决定节奏，循环片首尾帧完全一致。〔PLM〕
- **工程**：所有样式由时间 `seek(t)` 计算（暂停的时间轴逐帧定位），无 CSS transition、无计时器、帧间无状态；先每拍渲一帧做联系表，修正后再全片渲染。〔PLM〕〔CBF〕
- **评审**：每个镜头取一张稳定帧做联系表 → 按 `visual_critique_and_polish.md` §2 打分 → 修前三个问题 → 重渲，最多三轮。

## 7. 移动端与响应式

- 触控目标 ≥44×44pt（iOS）/ 48×48dp（Android），目标间距 ≥8px；热区可大于视觉边界；按下反馈 80–150ms 内出现且不改变布局尺寸。〔UX〕〔TU〕
- 390px：单栏；分栏一律"文字在先、图在后"堆叠；Hero 按钮可全宽，或在同一行放得下时并排；菜单为全屏面板（行高 56px）；任何内容不被固定栏遮挡（滚动内边距 = 固定栏高）。〔TS〕
- 字号：1024 以下相邻层级 ≥1.2×；h1 在手机 28–60px 且 ≤3 行；文字永不为了装下而缩小。〔TS layout-v4〕
- 间距：保持三档层级的**比例**，区块内边距手机 96/48（上/下）级别；gutter 24px。〔TS system〕
- 安全区：固定页眉、标签栏、底部操作栏遵守 `env(safe-area-inset-*)`，并为滚动内容加相应内边距。〔UX〕
- 状态：按下/聚焦/禁用在浅深主题中同样可辨；禁用 = 降低强调（不透明度 0.38–0.5）+ 语义属性，不只是变灰。〔UX〕
- hover 不保证存在：关键信息不藏在 hover 里；hover 动效包在 `(hover: hover) and (pointer: fine)`。〔TU〕〔EK〕
- 不禁止缩放（无 `user-scalable=no` / `maximum-scale=1`）；320px 无横向滚动；200% 文字缩放不裁切。〔TU〕
- 交付前：375/390 竖屏 + 横屏、减弱动效、系统最大字号（Dynamic Type）、深色模式独立对比度、所有目标 ≥44pt。〔UX〕

## 8. 品牌与识别（速查）〔UD brand〕〔TS〕

- 先锁正式品牌名、logo 版本、可用字体、品牌色与必须保留的文案；品牌更新要列出影响到的媒介、组件和资产。
- Logo 从草图与单色剪影开始；用最小尺寸、浅底/深底、单色、反白检查可辨性；记录最小尺寸、净空、组合方式、禁用背景。
- 真实 logo 保持原色原形，不重画、不改色、不变形；品牌色与清晰度冲突时，品牌色留给大面积与装饰，小字与状态换一个可配对的前景色。
- 品牌规范落到 token（原语 → 语义 → 组件三层），网页与印刷分别实测。
